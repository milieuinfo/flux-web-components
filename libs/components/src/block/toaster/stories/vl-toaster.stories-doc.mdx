## Gebruik

### Declaratief

Je kan de meldingen declaratief toevoegen in het default slot van de `vl-toaster`, typisch gebruiken we
hiervoor de [vl-alert](/docs/components-block-alert--documentatie) component.
Het element verschijnt dan automatisch op de gekozen positie.

<Canvas of={VlToasterStories.ToasterDefaultSlot} />

### Dynamisch

De `showAlert()`-methode, is de eenvoudigste manier om een melding te tonen.
Achterliggend maken we een [vl-alert](/docs/components-block-alert--documentatie) component aan met de
opgegeven parameters.

```js
const toaster = document.querySelector('vl-toaster');
toaster.showAlert({
  type: 'warning',
  titleLabel: 'Technische storing',
  message: 'Uw aanvraag is niet verwerkt.\nFout code: 36981',
  closable: true,
  multiline: true,
});
```

Het meegegeven object ondersteunt alle attributen van de [vl-alert](/docs/components-block-alert--documentatie)
component in camelCase, zoals `multiline` om regeleinden (`\n`) in de `message` te bewaren of `alertRole` om de rol
van de melding te kiezen. De attribuutnaam als key (`'alert-role'`, `'title-label'`) werkt ook. Een `title` zet de
titel ook, als `title-label` op de melding; staan beide er, dan wint `titleLabel`.

<Canvas of={VlToasterStories.ToasterShowAlert} />

Als je meer controle wilt over de melding, kan je ook de `show()` methode gebruiken om een zelf samengesteld
HTML-element te tonen als melding.

```js
const toaster = document.querySelector('vl-toaster');
// toont de melding gedeclareerd in het default slot van de toaster
toaster.show(document.querySelector('#warning-123')); // deze methode toont het meegegeven HTML element als toast
```

### Layout

We volgen de stijl van Digitaal Vlaanderen, waarbij standaard de breedte op `30rem` wordt ingesteld.
Een alert heeft standaard geen breedte en neemt de volledige breedte over van zijn container (de `vl-toaster`),
namelijk `30rem`.

Als er nood is hier van af te wijken, kan je de `width` van de `vl-toaster` zelf aanpassen.
Vermijd hierbij het gebruik van inline styles.

Je kan hiervoor de `--vl-toaster-width` custom variabele aanpassen, bv.:

```css
.pagina {
       --vl-toaster-width: 50rem;
      }
```

### Fade out

We bieden de mogelijkheid aan om meldingen automatisch te laten verdwijnen met het `fade-out` attribuut op de
`vl-toaster`. Een melding verdwijnt dan ongeveer 5 seconden na het tonen.

   vooral als ze gebruik maken van schermlezers of andere hulpmiddelen.
`}
</FluxAlert>

#### Per melding

Je kan per melding kiezen of ze automatisch verdwijnt, met een attribuut op de melding zelf. De `vl-toaster` leest
die attributen, de `vl-alert` doet er zelf niets mee.

- `fade-out`: de melding verdwijnt automatisch, ook in een `vl-toaster` zonder `fade-out`.
- `persistent`: de melding blijft staan, ook in een `vl-toaster` met `fade-out`. Heeft een melding beide attributen,
  dan blijft ze staan.

Meldingen zonder een van deze attributen volgen het `fade-out` attribuut van de `vl-toaster`.

```html
<template id="alert-saved-template">
    <vl-alert fade-out type="success" icon="check" title-label="Bewaard">
        <p>Uw wijzigingen zijn bewaard.</p>
    </vl-alert>
</template>
```

Bij `show()` en `showAlert()` regel je hetzelfde met de optionele tweede parameter `{ fadeOut }`: `true` zet het
`fade-out` attribuut op de melding, `false` zet `persistent`. Die parameter heeft voorrang op de attributen die de
melding al heeft, bijvoorbeeld uit een `<template>`. Zonder parameter blijven die attributen gelden.

```js
const toaster = document.querySelector('vl-toaster');
toaster.show('#alert-saved-template');
toaster.showAlert(
  {
    type: 'error',
    titleLabel: 'Niet bewaard',
    message: 'Uw wijzigingen zijn niet bewaard. Probeer het later opnieuw.',
    closable: true,
  },
  { fadeOut: false },
);
```

Meldingen in het default slot verdwijnen nooit automatisch, ook niet met `fade-out` op de toaster of de melding.

#### Pauze bij hover en focus

Zolang de muis op de toaster staat of de focus erin zit, verdwijnt er geen enkele melding. Alle meldingen in de
toaster wachten dan, zodat ze niet verschuiven terwijl de gebruiker ermee bezig is. Daarna loopt de resterende tijd
van elke melding verder.


## Toegankelijkheid

### fade-out

Het `fade-out` attribuut doet meldingen automatisch verdwijnen, ongeveer 5 seconden na het tonen. Dat is een
tijdslimiet in de zin van
[WCAG 2.2.1 Timing Adjustable](https://www.w3.org/WAI/WCAG22/Understanding/timing-adjustable.html).

Vermijd het gebruik waar mogelijk gezien dit de toegankelijkheid van de toaster negatief beïnvloedt. Gebruikers kunnen
de melding mogelijk niet op tijd lezen of begrijpen, dit is problematisch bij het gebruik van schermlezers.
De pauze bij hover en focus helpt, maar een toetsenbordgebruiker bereikt een melding zelden op tijd.

Laat daarom foutmeldingen en meldingen met interactieve inhoud, zoals een sluitknop (`closable`) of het `actions` slot,
nooit automatisch verdwijnen. Geef ze het `persistent` attribuut of toon ze met `{ fadeOut: false }`.
